# Private local vault adapter

`createVaultController(ports)` is the portable policy core. Import `createProtectedNativeVaultController` from `./platform` and await it with `{onLock,onConceal}`; Metro selects `platform.native.ts`, and Node/web select the unsupported fallback. Only the authenticated session coordinator may construct `{ issuer, subject, sessionId }`. A role selector, guardian membership, account metadata or supplied subject is not authentication. The core does not call a backend or revalidate tokens: the coordinator must close it on signout, revocation and account change. Offline unlock is only for the previously enrolled author; immediate remote revocation while offline is impossible.

The preferred native factory is process-wide and exclusive: each request waits for the previous controller's `dispose()` before creating its replacement. Retirement is idempotent; failed retirement remains attached and rejects later requests instead of opening overlapping handles. Journal and private-message draft callers use this factory. Direct low-level independent controllers bypass that ownership mechanism and must not be created concurrently. Call `enroll(actor, signal?)` after explicit acknowledgement of device-key loss, then `unlock(actor, signal?)`. Both perform device authentication; keys also retain SecureStore authentication binding. A different author cannot enroll until an explicit own-author/device-authenticated `erase(actor, signal?)` removes the previous vault. Interrupted setup enters `recovery-required`; an invalid/missing key never creates a replacement. Erase retries an interrupted `deleting` state. Never automatically erase on error.

The preferred factory gets its directory exclusively from the local `BetweenUsProtection` Expo module. Android uses a canonical child of this application's `noBackupFilesDir`; iOS uses a fixed own Application Support directory and reapplies/reads back backup exclusions on that directory and every database/sidecar. Both reject symlinks and nested directories. The lower-level synchronous `createNativeVaultController({directory,protectAndVerifyDirectory,...})` is retained for integration, but its directory must match the native module's path and native verification still runs; a callback returning true cannot invent backup proof. Missing native modules/cipher support refuses persistent storage. No public document/share, evictable cache or browser plaintext fallback exists.

After unlock, `list({limit?,before?})`, `read(id)`, `save({id?,title,body,expectedRevision})` and `delete(id,expectedRevision)` address only the enrolled journal. New saves use `expectedRevision:null` and omit id; updates use returned id/revision. `listDrafts/readDraft/saveDraft/clearDraft` address a separately keyed database. `listDrafts(filter?:{kind?:PrivateDraft['kind'];title?:string})` applies exact, prepared equality filters before the latest-50 bound. It returns only id/title/createdAt/updatedAt/revision/kind; default no-argument behavior is unchanged. Filters reject unknown fields, invalid kind, title over 150 code units, NUL and unpaired surrogates. Conversation recovery uses kind `conversation` and the encrypted title `message-thread:<conversationUUID>`; no external ID registry is needed. Journal recovery uses kind `journal-editor` and null recipient/preference. No draft method sends, queues, verifies a recipient or reads a journal.

Production Journal discloses automatic private draft protection before unlock. Its editor saves changed snapshots after a 1,000 ms foreground pause only while the same author's vault is already unlocked; timers never unlock or call `touch()`. Editor stamps and the shared revision chain prevent old completions replacing new writing. Explicit Back/page changes flush or show a loss warning. Background/lock cancels pending work immediately without promising a final save; only a confirmed snapshot is protected. Manual Protect/recover/delete remain available. Separately composed conversation drafts still require explicit Protect and fresh author/recipient checks on recovery.

Call `touch()` for actual author input, not timers/model results. A two-minute timer locks access; monotonic operation checks also enforce the deadline if OS suspension delays that timer. `touch` cannot revive an expired session. `lock('background'|'idle'|'manual'|'signout'|'account-change'|'revoked')` immediately revokes access and returns a promise for draining/closing. Supply `onLock(reason)` to synchronously cover/unmount and clear sensitive UI and cancel/drain its model. Supply `onConceal(covered)` for a separate opaque transient privacy cover: clearing that cover never unlocks an account or restores cleared content. AppState inactive conceals immediately; inactive events caused by this adapter's own LocalAuthentication/SecureStore prompt preserve the pending lifetime, while unrelated inactive events and every real background event invalidate it. Native authentication waits at most two seconds for active resume; final unlock/results require active AppState and unchanged actor lifetime. A stale/cancelled prompt cannot unlock after signout/background. Await a lock before another unlock. `dispose()` removes subscriptions/timers and permanently closes this controller.

Queue inputs and results belong to the captured lifetime. A lock prevents queued saves from starting and rolls back a transaction whose work became stale before commit. A commit that already crossed the native boundary may persist; its stale result is always withheld. Never interpret a rejected save as proof that a commit did not happen; reread after the same author unlocks. SQL/keys/native errors are not surfaced; catch `VaultError.code` for fixed UI copy. Authentication failures must offer retry/back, not reset. No error should be sent to telemetry.

`preparePlaintextExport(ids)` performs fresh device authentication and returns selected records as a bounded JSON string in memory only. The UI must obtain explicit own-author selection/review/disclosure before invoking it and clear the returned string on lock. It never writes/shares a file and supplies no encrypted export/recovery format. The destination/export lifecycle still needs a separately reviewed implementation. Whole-vault erase requires an explicit destructive confirmation in the caller; the adapter cannot display that confirmation.

Schema version 1 uses a metadata row plus `entries` in each physically separate database. The draft database's rows additionally use kind/recipient/preference; the journal writes those fields null. Only one private serialized connection accesses each database; manual BEGIN/COMMIT/ROLLBACK remains on that keyed connection. Revision checks, per-database 1,000-row/16-MiB limits, input bounds and stale-result guards run inside the adapter. SQLCipher availability is checked before key/schema access on every connection, followed by metadata/integrity validation. Unrecognized schemas are refused. No plaintext migration, key rotation, cloud/guardian recovery or journal synchronization is implemented.

Root's central private-writing lifetime separately clears unsent conversation/report/preparation UI and invalidates old draft handlers on background or two minutes without author input, including after leaving the composer. Unattempted Review is discarded; an already attempted immutable command is hidden and retained for explicit outcome resolution. The separately keyed `approved-message-outbox` stores only exact commands approved by explicit Send, before transport; it never opens journals or private drafts and never automatically retries. Its device-unlocked key policy differs from this biometric vault; see [outbox contract](../../../../../spec/production/MESSAGE_OUTBOX.md).

The outbox now requests a separate module-verified fixed sibling directory, preserving this vault's original path and strict orphan-file refusal. Its native methods fail closed if legacy `message-outbox-v1-*` files remain in the vault directory; they never move/delete/reset those records. Affected staging installations need reviewed recovery before either workflow can be considered available. Native rebuild and first-send-before-Journal/legacy-refusal regressions remain pending; current TypeScript/scoped ESLint pass does not prove native filesystem behavior.

Portable tests use real in-memory SQLite with fake SQLCipher, filesystem and key ports. The root operator observed the p1 Android debug probe pass SQLCipher 4.17, native no-backup-path checks, ciphertext/wrong-key rejection and correct-key reopen. That diagnostic predates the outbox sibling-directory change; it does not establish the full author-vault lifecycle, physical biometric custody or backup/restore behavior. Physical Android/iOS, capture, restoration, memory/model and independent review gates remain in [storage contract](../../../../../spec/production/JOURNAL_STORAGE.md). No native operations or new unit tests were run for this directory/documentation update.
