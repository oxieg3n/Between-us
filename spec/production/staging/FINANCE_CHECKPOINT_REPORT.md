## What changed

- Validated immutable checkpoints fold the bounded hot tail. Original accepted events, operation UUIDs, fingerprints and every archive version remain stored.128visible/32private tail windows and100occurrence/32payout active-work limits were retained.
- Settled source-connected components archive together with exact original allocation, payment and earning provenance. Live money never disappears into a summary. A correction hydrates the exact source-bound component, removes its folded paid basis once, applies the existing integer-cent command and appends a new immutable event.
- Fully invalidated parent matches use separate private capsules and exact monthly/goal summaries. Parent reveal/reconciliation can hydrate old commitments. Private state never determines eligibility for visible retirement; original potential provenance is retained even when matching is disabled.
- Permanent entity/command registries prevent lifetime ID reuse. Current-pointer/residency indexes select retained versions without replaying lifetime history. Checkpoint/capsule hashes and source sequence/CAS bindings fail closed on corruption; a checksum does not replace semantic validation or trusted server authority.
- Service-only, role-authorized20-record pages expose settled history. A separate parent-only open-matching page makes live commitments beyond the100-record summary discoverable. Explicit mobile review supports old earning/payment corrections, receipt acknowledgment, funding, reveal and reconciliation; no action moves external money.
- Each archive-aware service command atomically captures role-safe audit activity and projections. Exports merge current hot/archived financial entities and complete chronological authorized activity; they are not a raw dump of every immutable event or capsule version. Missing/corrupt coverage or oversized artifacts require review instead of a partial file marked complete. Raw source maps/checkpoints/hashes and surprise fields never enter child exports.
- Indexed admission permits at most60new writes/minute per actor/child/visibility stream,1,000visible/day per child and200private/day per child. Exact replay does not consume another admission. Denial rolls back ledger, checkpoint, archive and captured projections together.
- Sealed read-only working books avoid duplicate sibling replay/copies. A successful new commit returns a compact acknowledgment; only the exact accepted candidate/server time is reused. Racing replay still returns and projects current database state.
- Migration031 makes page payload reads parameterized point lookups after limiting residency keys. It prevents a statistics-dependent broad capsule join observed during benchmarking. Active source integrity, current parent authority, cursor checks, response bounds and grants are unchanged.

No journal contents, drafts, model prompts, provider balances, new credentials or real transfers enter this feature. The public demo and approved branding remain separate and preserved.
