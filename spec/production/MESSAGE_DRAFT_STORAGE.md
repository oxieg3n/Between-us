# Private protected message drafts

2026-11-16. This source adds optional, explicit native Protect/Recover controls to the production conversation. It does not send, queue, share or automatically review a message. Root owns Application wiring, the shared vault factory barrier and actual native verification. Fictional-only development and the existing release gates remain.

## Storage and authority

The default native adapter uses the existing protected author-local SQLCipher vault factory and the separately keyed drafts database. It retains the existing strong biometric requirement, device/key binding, private directory and native no-backup verification. Missing cipher/protection/biometry support or another enrolled author stays closed. No custom encryption, cloud path, new dependency, plaintext fallback or SecureStore message-body workaround was introduced.

Before unlock/setup and every storage operation, the native adapter reuses `verifyJournalAccess` with managed `getUser`, server-verified claims (`verifiedSessionClaims`) and current server `get_context`. The returned issuer/UID/session/role must match the expected author and the unlocked lifetime. Cached context, user metadata, parent/guardian role or a caller-supplied UID cannot mint access. Same-session token refresh can reverify; a different session requires another deliberate unlock. No offline authorization fallback was added.

Existing schema kind is **`conversation`**, not `message`. The encrypted title `message-thread:<conversationUUID>` binds a protected copy to its thread; `recipientCandidate` stores the exact peer Auth UID and `responsePreference` stores `listen`, `reply`, **`later`**, or `talk` without substitution. Body length is at most5000 JavaScript characters and existing vault validation/quotas remain. No access token, session secret or journal body is stored in this draft.

Discovery uses the core's new `listDrafts({kind:"conversation",title:marker})` equality filter **before** its50-result limit, then defensively filters again. It never invokes journal-entry list/read/save/export APIs. Only current-thread message summaries are rendered. The shared core may open both keyed databases and check their metadata/integrity during unlock; it does not return journal entry contents to this adapter. At most50 recent copies for this particular thread are shown; older matching copies are not deleted or silently treated as absent.

## Explicit user controls

- **Unlock private message drafts** verifies the author, then invokes the existing device authentication. Entry into the conversation alone performs no biometric prompt or vault open.
- **Set up my private device storage** is separate and requires acknowledgement that one author is enrolled on the installation and key loss can permanently lose writing. It calls existing `enroll` then unlock. It never falls back from a failed unlock into enrollment; existing/foreign/interrupted storage is not overwritten or erased.
- **Protect this message** snapshots the author's current words and response preference. Later Protect updates the same selected copy using the vault revision check. Protect is a private own-author action and does not claim that a recipient has accepted/been verified or that anything was sent.
- **Find protected copies** returns metadata only. Choosing a summary still does not load or restore its body. A separate **Recover selected copy into composer** action does that explicitly and warns that it replaces current unsent words.
- Recovery checks the current recipient before and after its selected local read, validates kind/title/peer/preference/body, and re-verifies the same author/session after the read. It returns words only after those checks and current foreground/lifetime checks. It cannot recover another thread's copy by guessed ID.
- **Lock private message storage** closes access and clears only the still-current scope's composer via the Root callback. No background or navigation event promises a final save. Protected copies are not automatically deleted on review or send; later recovery remains a deliberate action with a separate review step.

Ordinary typing is memory-only until a successful manual Protect. The UI compares the exact protected snapshot with current words/preference, so subsequent edits are labelled unprotected. A storage error/conflict does not claim success or discard current ordinary edits. A save can have crossed a native commit boundary before interruption; its late result is withheld, and the same author must unlock/check saved copies rather than assuming either success or no commit.

## Lifetime and privacy barriers

Author, issuer, conversation and peer define the component/storage lifetime. Callback/appearance/font-size changes and ordinary typing do not reconstruct it or reset drafts. Background and account events lock/cancel work. Protected summaries, selected IDs and success markers are cleared on lock; Root receives a scope-bound clear request for current composer text/preference. A stale author/thread cannot clear another author's or a newer thread's words. Transient native authentication covers the whole conversation without treating its own inactive biometric UI as a successful background flush.

When covered, inactive, backgrounded or bound to a stale scope, the sensitive conversation/composer is removed from the rendered accessibility tree and replaced by an opaque cover. Native screen-capture prevention must be established before private unlock/setup controls are enabled; cleanup releases only this component's capture key. Root remains responsible for its review screen/global background barriers after navigation, including any recovered words deliberately placed in Root memory.

The protected factory must be exclusive across Journal and Conversation. Root is adding the shared factory/dispose barrier so the old controller drains/closes before another is created; retirement failure must stay closed. A test/custom `vaultFactory` is a trusted integration port, not a user-selectable way to bypass SQLCipher or device protection. This helper does not change the vault core/native implementation, Journal or global navigation.

Browser/private-draft support is explicitly unavailable. Conversation typing remains in memory and no browser persistence is created. The web adapter refuses private storage even if a caller supplies a factory; browser UI does not offer a misleading encrypted/protected success.

## Root props contract

`ProductionConversation` accepts an optional `privateDraft: PrivateMessageDraftControls` with:

| Field | Root responsibility |
| --- | --- |
| `context`, `conversationId`, `peerId` | Current server account context and actual thread/peer; component checks context UID against `ownId` |
| `isCurrent(scope)` | Synchronous check of the **managed account lifetime plus** issuer/author/thread/peer; IDs alone must not accept a later re-login with the same UID |
| `verifyRecipient(scope,signal)` | Fresh, expected-UID-bound server conversation/contact authorization; require the same thread and peer, currently accepted/approved/verified/usable/unblocked. Ignore stale results and respect cancellation. |
| `onClear(scope)` | Clear only current bound Root words and response; must be a no-op for another author, new session or changed thread. Never describe this as a flush. |
| `onRecover(scope,{words,response})` | Repeat the lifetime/ID check, then call Root's current word/response setters only. Never invoke Review/Send or attach journal content. |
| `vaultFactory?` | Optional trusted test/integration factory; production default is the protected exclusive native factory |

Root's existing Review still revalidates the recipient and asks for an explicit separate send. The new component never calls `onReview` as part of unlock, protect, list or recover. Existing global Back may keep Root's memory draft; disposal locks local storage and does not flush, claim to protect, or silently erase Root's deliberate review state.

## Capture handoff to Root review

The separate `usePrivateMessageCapture(scopeKey:string|null)` hook is prepared for Root wiring. Keep a non-null private capability scope while protected recovered words are visible in Conversation **or** held for the explicit Root Review. The scope should bind the verified author/session/thread/peer; it must not contain message text, credentials or journal content. Do not set it to null merely because the Conversation component unmounts for review. Root may end the scope after its corresponding private words/review payload are cleared or no longer renderable.

For a non-null native scope, the first render is always `{covered:true,error:false}` until its own asynchronous native prevention completes. The hook memoizes a fresh activation object on key changes, including `A -> null -> A`. Readiness belongs to that object, not string equality, so returning to the same screen after departure or unmount cannot reuse an old ready flag. A failed protect remains covered with `error:true`. Root must replace/hide private pixels **and** accessibility content whenever covered or errored; a ready network/vault state cannot bypass this gate. Null is normal public UI. Browser non-null scopes return covered/error and never claim native capture protection.

Every effect owns a new UUID tag. Cleanup marks its lease disposed immediately, waits for pending native prevention to settle, then calls `allowScreenCaptureAsync` with **only that tag**. It never calls unscoped/global allow or releases another component's tag. Late success/failure cannot ready a newer activation. A release failure stays restrictive and is not “fixed” by enabling all capture. The existing Conversation's own keyed barrier can retire while Root's keyed lease remains; use the installed Expo keyed API rather than direct native/global flag manipulation.

Owned capture-file lint passes. This is source lifecycle evidence; Root still owns hook wiring, opaque/accessibility cover behavior and actual native screenshot/recording/app-switcher verification. No capture check grants permission to review/share automatically, and the hook never invokes review or send.

## Author-wide unsent writing lifetime

The pure `createPrivateWritingLifetime` coordinator must stay bound to one verified author/session in Root while navigation moves between Conversation, Home and Review. Component disposal alone cannot clear Root's retained composer map. Its ports are `current`, `monotonicNow`, `attempted`, `clearUnsent`, `invalidateDraftHandlers`, `discardUnattemptedReview` and `hideAttemptedReview`; its methods are `touch`, `lock`, `tick` and `cancel`. `tick` uses a two-minute monotonic idle deadline. Only actual author edits call `touch`; timers, model output, renders, navigation and network completion do not extend the deadline. `lock` is used for both background and explicit manual locking, including background immediately after creation at timestamp zero.

A current lock clears Root's unsent composer copies, invalidates the private-draft callback epoch, then discards an **unattempted** review. An already attempted command whose result may be unknown keeps its exact immutable operation identity/body privately for retry; Root hides its body and shows locked wording with an explicit exact retry action. Locking never resends, resets or reports that operation as unsuccessful. `touch` cannot restore or unhide that attempted review. Root must implement those separate ports accordingly and keep financial forms outside the private-message draft epoch.

Stale-author/cancelled controllers perform no mutations. A lock does not repeat on every timer tick; only subsequent actual input starts another idle interval. `touch` checks the elapsed deadline before accepting an edit: if the timer was delayed, the first overdue input locks expired writing and returns `false`. Root must discard that edit and recheck the private-draft epoch. A subsequent deliberate input can start a fresh memory draft; it never restores the expired writing or an attempted review. `cancel` retires callbacks without claiming a save or performing an old-account clear. This helper has no React, vault, persistent storage, network or key access and does not erase already protected local copies. Six focused tests cover retained Home/Review drafts, attempted-command preservation/body hiding, stale/cancelled callbacks, callback scope changes, monotonic idle boundaries, delayed-timer overdue input and real-input resets. Root still owns wiring background/timer/input events, account-bound callbacks and actual device verification; no final background flush or irreversible memory wipe is claimed.

## Independent reviewed-send threads

`createReviewedSendCoordinator({authorId,sessionKey},send,makeId)` wraps the existing reviewed sender without changing final server authorization. Root supplies a key bound to the verified issuer/author/session lifetime; this key is a local lifetime marker and grants no permission. `forThread({authorId,conversationId,peerId})` returns a stable sender exposing `stage`, `submit`, `uncertain` and `snapshot`. The same conversation cannot change its peer. A thread's unknown send keeps its original frozen UUID/body/response/recipient exclusions for explicit retry while another thread can compose/send independently and Journal remains available. Root should retrieve `snapshot()` when reopening that thread and apply its existing locked-body presentation; nothing here automatically navigates, reviews, sends or restores words into a composer.

`pendingThreads()` returns a frozen list of own author/conversation/peer/uncertain metadata, with no body, response, recipient exclusion policy, operation ID or session key. Author background/idle locking calls `clearUnattempted()` to remove only staged, never-attempted private reviews. Unknown/in-flight and adopted approved commands retain their exact retries; other thread handles remain usable for fresh writing. `resetAll()` permanently retires that controller and every old thread handle; a new account/session gets a fresh controller. Old in-flight completions cannot clear a new controller's command. Stage/submit on retired handles fail; old snapshots and pending listings become empty.

The optional `thread.adopt(envelope,{attempted:true})` integration port accepts a separately authorized, validated durable `ReviewedMessage`. It retains the saved UUID without calling `makeId`, copies/freeze-protects the exact words/response/exclusions, checks author/thread/peer, and immediately marks the command uncertain/read-only without transmission. Re-discovering the exact same command is safe; a different identity, body, response, policy or scope cannot replace an existing command. Root's separately assigned protected outbox owns storage verification and resolution; this coordinator itself has no persistence or vault access and makes no process-restart recovery claim on its own. Adoption never implies current recipient authorization and explicit retry must still run the ordinary server checks. Confirmed acceptance/rejection uses the existing sender's outcome behavior.

Seven new focused coordinator tests plus the existing four sender tests cover independent Alice/Bob sends, exact reopening/retry, scoped peer/author denial, metadata minimization, old-account async retirement, per-thread double-tap/rejection isolation, saved-envelope adoption without automatic send or replacement identity, and selective clearing on writing lock. Actual Root navigation/outbox wiring and device checks remain integration work.
